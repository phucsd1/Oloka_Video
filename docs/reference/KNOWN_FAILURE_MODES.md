# Known Failure Modes

## Severity

- **Critical:** có thể xóa/lộ dữ liệu diện rộng, vượt ranh giới project hoặc làm mất khả năng phục hồi.
- **High:** chặn journey chính, gây mất artifact/job hoặc tạo output sai mà người dùng dễ tin là đúng.
- **Medium:** làm một capability suy giảm, gây nhầm lẫn hoặc cần thao tác thủ công để phục hồi.
- **Low:** chủ yếu là maintainability, observability hoặc polish.

Đây là rủi ro `SOURCE_VERIFIED` và `NOT_RUNTIME_VERIFIED`, không khẳng định mọi lỗi đã xảy ra trên production và không phải kết quả exploit/PoC. Nguồn audit: `595ccdfaf45ff83473f2da8fd2c71d491828e5f5`.

## Critical/High cần chặn trước MVP

1. Opaque project IDs và containment tuyệt đối cho mọi file operation.
2. Soft-delete/restore và durable storage versioning.
3. Một canonical project/job state model; không suy luận state từ log.
4. Durable queue với lease, retry, cancel và resume idempotent.
5. Secret manager + tenant-aware asset authorization.
6. Immutable render artifact và provider protocol versioned.
7. Chỉ một deployment topology và một orchestration API.
