## API conclusions cho Oloka

- Giữ một command API cho generation/edit/render, không duy trì direct pipeline endpoints trùng Forge.
- Tách command acceptance (`202`) khỏi durable job/read model/events.
- Mọi resource dùng opaque ID và tenant scope; không để filename/path làm identity.
- Upload/download dùng object storage URL có checksum/quota, không raw body qua app cho file lớn.
- Sinh OpenAPI/typed contracts và route reachability tests để tránh router tồn tại nhưng không mount.
- Admin/provider/social APIs cần authorization policy thống nhất và idempotency/audit.
