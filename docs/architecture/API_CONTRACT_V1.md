# API Contract V1

Status: capability map and transport contract; no route implementation exists from this document.

## Protocol conventions

- Product API paths are `/api/v1/**`. Foundation probes remain `/api/health`, `/api/ready`, and `/api/version`.
- JSON contracts are strict Zod schemas exported once from `packages/contracts`; unknown keys fail with the canonical error envelope from `ERROR_MODEL.md`.
- UUID resource IDs are opaque. Unauthorized private resources are indistinguishable from missing resources (`404 RESOURCE_NOT_FOUND`).
- All unsafe cookie-authenticated requests apply `AUTH_SESSION_CSRF.md`.
- First-admin bootstrap is part of the verified Google callback transaction and
  has no separate HTTP route. Admin role/status mutation enforces the
  last-active-admin guard; emergency recovery is operator maintenance only.
- Important mutations require exactly one `Idempotency-Key` containing 1-128
  ASCII characters from `A-Z a-z 0-9 . _ : -`. Missing, empty, multiple,
  Unicode, whitespace, control, slash, backslash, quote, or oversized values
  are `400 VALIDATION_ERROR`. The server hashes the key and canonical semantic
  request; same key/same request replays the stored result and same key/different
  request is `409 IDEMPOTENCY_CONFLICT`.
- Mutable resources expose an integer `version` and ETag. Updates require `If-Match` or `expectedVersion`; stale writes return `409 VERSION_CONFLICT` with current safe version, never silently overwrite.
- Lists use an opaque base64url cursor containing versioned canonical sort position, filter fingerprint, and ID tie-breaker. Default/max page sizes are 25/100. Sorting is deterministic; cursor/filter mismatch is `400 INVALID_CURSOR`.
- Times are ISO 8601 UTC strings at the HTTP boundary and epoch milliseconds in SQLite.
- IDs, not storage keys/paths/provider secrets, cross the API boundary.

## Common errors

The stable code, status, retryability, message key, action, severity, and allowed
surface come only from `ERROR_MODEL.md`. Common mappings are
`400 VALIDATION_ERROR`/`INVALID_CURSOR`, `401 AUTHENTICATION_REQUIRED`,
`403 AUTHORIZATION_DENIED` or an account-status code,
`404 RESOURCE_NOT_FOUND`, `409 RESOURCE_STATE_CONFLICT`/`VERSION_CONFLICT`/
`IDEMPOTENCY_CONFLICT`, `413 PAYLOAD_TOO_LARGE`,
`415 UNSUPPORTED_MEDIA_TYPE`, `416 RANGE_NOT_SATISFIABLE`, typed 422 domain
codes, `429 QUOTA_EXCEEDED`/`RATE_LIMITED`/`PROVIDER_RATE_LIMITED`, typed
502/503 provider or storage codes, and `500 INTERNAL_ERROR`. Every response
contains safe `code`, localized `messageKey`, `suggestedAction`, `retryable`,
`requestId`, and optional allowlisted field details; never a stack or provider body.

## Cursor shape

The opaque cursor encodes versioned canonical sort position, filter hash, and
UUID tie-breaker as base64url JSON plus HMAC-SHA256 under an HKDF-derived app
key. The implemented admin-user cursor is `{v:1, sort:{createdAt,id},
filterHash}` and binds normalized status/search. It never contains email,
display name, secret values, storage keys, provider operation IDs, or token
material. Invalid encoding/MAC/version/key/filter is `400 INVALID_CURSOR`;
default/max page sizes are 25/100.

## Contract ownership and evolution

Request, response, event, cursor, error, and composition schemas live in `packages/contracts` and are imported by both Fastify and React. API v1 additions are backward compatible; breaking shape/meaning requires a new API or schema version. OpenAPI may be generated from the canonical Zod contracts in Phase 3, but generated output is not a competing source of truth.

The capability map contains 72 sequential capabilities. Render cancellation and
retry use only the generic Job commands; no parallel render-specific command
routes exist. Owner-facing Project, CompositionVersion, Job history/status and
SSE routes are owner-only. Administrators inspect Jobs only through the redacted
admin list/detail/command surfaces, which exclude prompts, private bytes,
storage paths/keys, raw provider payloads, and owner SSE.
